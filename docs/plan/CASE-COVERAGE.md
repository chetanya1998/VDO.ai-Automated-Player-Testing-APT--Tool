# Required case coverage

All 23 cases from the supplied VDO.AI Implementation Validator test document are required in the plan. Mapping is not evidence of implementation or execution. Every case is currently planned and untested.

Source: VDO.AI Implementation Validator – Test Cases & Build Plan (3).docx, supplied 13 October 2026; sections 4, 13 and 14. The document is a draft. Product cases are requirements; its meeting instructions and next steps are not commands to execute.

This table is the acceptance index. Implementers read only the rows named by their task, plus applicable entries in DECISIONS.md. CASES.json contains the same mapping for future test manifests.

| Case | Implementation tasks | Acceptance scenarios | Conditions to resolve |
|---|---|---|---|
| TC-1 Correct tag and vdo.ai.js loading | [07](tasks/07.md), [23](tasks/23.md) | Capture the expected a.vdo.ai/core/<TAGNAME>/vdo.ai.js request; verify the approved tag, script type and HTTP 200. Test missing/wrong tag, 4xx/5xx, cancellation and blocking. Compare payload, script and DOM identities. | Expected tag mapping is authoritative; deriving it from a hostname alone remains unconfirmed. |
| TC-2 Load time of vdo.ai.js | [24](tasks/24.md) | Measure total request duration in a cold-cache run. Test 499, 500, 501, 1000 and 1001 ms plus timeout. Proposed bands: PASS <=500 ms, WARNING >500 to <=1000 ms, FAIL >1000 ms or timeout. | Record cache/network conditions. Confirm thresholds before production enforcement. |
| TC-3 Tag loads only once | [07](tasks/07.md), [26](tasks/26.md) | Count requests and matching implementation elements per tag and page/article epoch. Two different tags are valid; duplicate same-tag injection fails. Capture initiators and DOM mutations. Test duplicate script, duplicate anchor, legitimate distinct tags and a floating unit. | Floating units need no anchor. Define bootstrap versus injected external script counts and SPA reinsertion policy. |
| TC-4 Logger requests are firing | [05](tasks/05.md), [22](tasks/22.md), [08](tasks/08.md) | Capture logger/logger.php requests including xhr and ping, payload, status, initiator and duration. Test present HTTP 200, non-200, no requests and incomplete capture. Attribute absence only after script execution and the observation window. | Browser collection is sufficient; backend API access is not a prerequisite. |
| TC-5 Logger event sequence | [11](tasks/11.md) | Recognize ad-served Flow A and explainable no-ad Flow B. Test missing critical events and interrupted prerequisites while allowing independent ordering and subsequent ad cycles. Preserve raw names and start-time sequence. | Confirm exact aliases and critical conditions. Example Flow A places viewability before playback, conflicting with TC-6/TC-10. |
| TC-6 Individual event checks | [11](tasks/11.md), [25](tasks/25.md), [29](tasks/29.md) | Cover Loaded, initVdo, conditional Forceplay/Auto_Plays, Pageview, Website Pageview, ATF/BTF, Came In View, eligible Ad Request, Ad Match, Video Loaded/Start, both Pageview Match events, Viewable Impression and conditional Replay. Test each required missing event in its eligible scenario. | Video Start in no-ad content flow must not require an ad Video Loaded. Criticality is profile-dependent. |
| TC-7 Pageview counts | [11](tasks/11.md), [26](tasks/26.md) | Test one and multiple active tags: exactly one tag Pageview each and Website Pageview in {0,1} across tags. Detect excess and missing counts; distinguish expected blocks from unexplained formation failures. | Confirm Website Pageview scope across virtual articles. Do not confuse a count of zero with missing capture. |
| TC-8 ATF BTF and Came In View | [25](tasks/25.md) | Exercise initial ATF, BTF followed by scroll, and early scroll before loading completes. Exactly one ATF/BTF state per eligible tag; Came In View must occur when exposure is observed. | Use viewport state at the relevant event, not only original document placement. |
| TC-9 Ad request | [11](tasks/11.md), [12](tasks/12.md), [29](tasks/29.md) | For an eligible initialized and visible player, test Auto_Plays/Came In View leading to Ad Request or a confirmed equivalent. Inject missing/blocked demand requests and failed prerequisites; cite allowed_url and autoplay evidence. | Disabled demand or expected policy blocking changes applicability, not publisher correctness. |
| TC-10 Ad serving chain and viewable impression | [12](tasks/12.md), [25](tasks/25.md), [14](tasks/14.md) | Identify the first supported gap in Ad Request -> Ad Match -> Video Loaded -> Video Start -> Viewable Impression. Measure >=50% visibility continuously for >=2 seconds for video or >=1 second for banner. Test interrupted exposure and exact boundaries. | Optional Active View bs/mtos/p are supporting evidence only. No Ad Match alone is INVESTIGATE Demand, not an implementation failure. |
| TC-11 Blocked events and errors | [29](tasks/29.md) | Classify Blocked Player, BlockedInline, BlockedAutoPlay, Blocked IMA, Blocked Agent, Blocked Device, Error including Q2/Bn, and Blocked URL. Verify expected configuration and record browser/device plus preceding evidence. | Test expected versus unexpected blocks. Five Forceplay attempts require observable attempt evidence; do not infer them from one event. |
| TC-12 Dependency loading | [29](tasks/29.md), [05](tasks/05.md) | Check required vdo.ai.js, analytics.js, allowed_url, min.js, ima3.js, vdo.player.js, prebid.js and rtb.js against the product profile. Cover HTTP 200, missing, blocked and failed files before attributing missing initVdo to placement. | Not every product requires every file. Record transport/configuration cause separately from suggested owner. |
| TC-13 DOM check | [07](tasks/07.md), [26](tasks/26.md) | Verify correct unique anchor and external script, intended non-floating body/content placement, and unexpected removal/recreation. Test missing anchor/Q2, duplicates, wrong ID, wrong placement and valid floating without anchor. | Collect DOM evidence throughout the run, but present this stage after logger checks as requested. |
| TC-14 Player formation and CSS layout | [25](tasks/25.md) | Test formed versus unformed player, zero dimensions, display/visibility hiding, ancestor overflow clipping, z-index occlusion, transforms, parent layout and fixed/sticky/floating behavior. Distinguish formation failure from publisher CSS obstruction. | Unobservable cross-frame geometry stays UNKNOWN rather than fabricated viewability. |
| TC-15 Timing of logger events | [24](tasks/24.md) | Record every logger request duration and consecutive-event gaps separately. Test <=500 ms, >500 ms, isolated and repeated spikes, timeout and unavailable timing. Provisional >500 ms warnings must preserve raw measurements. | Repeated/large-delay FAIL limits and event-gap thresholds are unspecified. Exactly 500 ms is not above the proposed threshold. |
| TC-16 Device coverage | [27](tasks/27.md) | Execute applicable cases on desktop and a named mobile profile, including inline/autoplay/device blocks, playback after tap, placement, dimensions and viewability. Use real iOS/Safari evidence for claims about iOS restrictions. | Emulation cannot prove real-device behavior. Tablets and CTV remain later phase; missing required real-device evidence is reported unverified. |
| TC-17 Payload consistency | [22](tasks/22.md), [23](tasks/23.md), [26](tasks/26.md) | Compare tagName to the script/anchor per tag; domainName to the approved site; page_url to the event-time article; dep within page load. Test wrong/mixed tags, wrong domain, stale article and inconsistent build. | Multiple different tags are legitimate. Missing fields are TC-20 warnings; do not manufacture mismatches from absent values. |
| TC-18 Tag to domain match | [23](tasks/23.md) | Validate approved product prefix v/c/s/b, configured root-domain mapping and legitimate -v1/-v2 suffixes. Test subdomains, .co.in, valid multiple tags, wrong domain and wrong product. | Examples alone do not establish a universal derivation algorithm. Unconfirmed mapping is UNKNOWN. |
| TC-19 Dependency build check | [22](tasks/22.md) | Detect dep changes within one physical page load as FAIL. Test consistent build, changed build, empty field and dependencies_dev_3153 on a production profile. | The meaning of dev is unconfirmed: report an observation until configured policy establishes a development-build WARNING. |
| TC-20 Event name and field sanity | [22](tasks/22.md) | Validate nonempty event, tagName, domainName, page_url and dep; warn on unknown event names or missing/invalid fields. Keep raw event strings and explicit versioned aliases. Test malformed JSON and ignore unrelated payload fields. | Engineering must supply exact vocabulary; unknown future events must not crash parsing or silently disappear. |
| TC-21 Current article URL equals logger page_url | [26](tasks/26.md) | Snapshot current URL at request start; compare each event with its article epoch. Test matching URL, stale previous article, redirect and query/hash/trailing-slash variants. Delayed responses from the previous article retain their original event-time scope. | Strict comparison is the draft baseline; permitted URL normalization needs confirmation. |
| TC-22 loaded and pageview once per article URL | [26](tasks/26.md), [11](tasks/11.md) | Per run/article/tag count loaded=1 and pageview=1. Test duplicate loaded, duplicate pageview with one loaded, pageviews across articles with one loaded, and loaded without pageview. Preserve block/error reasons and multi-tag isolation. | Apply the document's draft per-article contract; confirm reinitialization versus physical script reload and revisit behavior. |
| TC-23 Infinite scroll and SPA scenario | [26](tasks/26.md), [27](tasks/27.md) | Keep capture active through at least three distinct articles via scroll or same-document navigation. For every tag/article assert current page_url plus one loaded and pageview; test stale URL, missing reload event and duplicate events. | Requires a site-specific safe transition action and approved SPA lifecycle contract. Failure to reach three articles means incomplete coverage. |

The screenshot descriptions in source section 5 are examples, not fresh test results. No embedded screenshot images were present in the supplied DOCX. The example payload validates only the supplied fields, not the entire event dictionary.

Release accounting: retain one result per TC, tag, article and device profile. Support PASS, FAIL, WARNING, UNKNOWN and NOT_APPLICABLE. Store reason, expected/observed values and evidence IDs. Do not mark a case covered in the product until its required scenarios pass and relevant rule decisions are confirmed.

# Rule decisions before enforcement

The supplied test document is a draft. All TC-1 through TC-23 are in scope, but the rules below need confirmation before a production conformance claim. Development may proceed with explicit draft profiles and synthetic fixtures. None of these entries is an instruction to contact the team automatically.

| Decision | Source tension or missing detail | Working approach | Suggested owner |
|---|---|---|---|
| D01 Expected tag and product | TC-18 gives root-domain examples but leaves subdomains and multipart suffixes open; v/c/s/b support versus video-only v1 is undecided | Accept expected tag/product mappings in a versioned profile. Auto-detection is a candidate list. Test all prefixes synthetically; publish which product profiles are actually validated. Do not infer ownership from string resemblance. | Player engineering and Ad Ops |
| D02 Event spellings | Display names such as Loaded, initVdo and Auto_Plays are mixed with payload examples such as loaded/pageview | Preserve raw values and approve explicit aliases per player version. Confirm rollout exceptions, if any. | Release engineering |

Define revisit/back behavior and Website Pageview scope across virtual articles. | Player engineering and analytics |
| D10 Block severity after recovery | Flow B includes BlockedAutoPlay while TC-11 classifies it as a runtime issue. Expected recovery may happen later | Preserve the block and its observed effects. It does not prove a join to backend events. Keep backend verification in tasks 09/10 separate; require a real shared key before confident server correlation. | Backend and player engineering |
